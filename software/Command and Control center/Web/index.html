03 / OPERATOR STATION

Ground control

Product control console for direct USB UART or a serial-to-ESP-NOW bridge. Telemetry is freshness-checked; unavailable measurements remain blank. Actuator outputs remain compile-time locked until the physical net map, axis transform, thrust allocation and failsafe are validated.
HARDWARE OFFLINE

Connection & control transport

USB UART · 115200 baud · local bridge

NOT CONNECTED
Direct serial connects to the rover; ESP-NOW mode uses the second ESP32-S3 as a USB-serial ground bridge, configured with the reciprocal peer MAC and same Wi-Fi channel.
Close Arduino Serial Monitor before connecting. Only one application can own the COM port at a time.
SAFETY INTERLOCK

Propellers must be removed for bench tests. ARM only after verifying the common signal ground, correct ESC wiring and clear motor area. Software cannot guarantee a safe state if wiring or signal reference is lost.

Two-step arming is required. START is not sent until the second confirmation.

OPERATING MODE

Water mode remains disabled because the water-propulsion mechanism and safe servo geometry are not validated. Air/land mode commands are rejected while armed or when outputs are not at minimum.

Controller tuning

Change gains only while disarmed · gains apply to the ESP32 firmware

DISCONNECTED

The firmware ships with ESC outputs compile-time locked. This tab can inspect sensors and tune/save gains, but it cannot make the vehicle flight-ready. Do not enable outputs until IMU axes, motor signs, servo geometry, and failsafes are verified.

ATTITUDE TRIMS · DISARMED ONLY
Trims are commanded setpoint offsets, not sensor-calibration values. Firmware acknowledgement and fresh telemetry are required. This firmware build keeps all actuator outputs locked.
SETPOINTS · EXPERIMENTAL
Altitude hold requires a validated barometer, a measured hover-throttle feed-forward, correctly signed vertical dynamics and a working inner attitude loop. It is not a position hold controller. The current firmware output gate is locked, so these controls cannot spin the motors.

Calibration procedure

Separate firmware · not run by the live control panel

HIGH RISK IF MISUSED
Calibration sends a high-throttle signal to the ESC. Remove every propeller, disconnect LiPo power before uploading, and follow your exact ESC manual. This tab does not silently start calibration or send 2000 µs to a connected vehicle.
Prepare safely

Remove propellers, secure the frame, disconnect LiPo and verify all signal grounds. Do not calibrate with an unknown ESC firmware or while the vehicle is assembled for flight.

Upload calibration firmware

Open firmware/esc_calibration/Callibration_Code.ino in Arduino IDE. This is a separate sketch; it replaces normal flight-control firmware until you re-upload it.

Explicitly request maximum signal

The revised calibration sketch boots at 1000 µs. With LiPo still disconnected, type PREPARE_MAX in Serial Monitor. Only then does it set 2000 µs for the manufacturer's calibration sequence.

Follow ESC tone confirmation

Connect LiPo only after the max signal is stable. When the exact maximum-throttle tones described by your ESC manual are heard, type CONFIRM_MIN to return to 1000 µs. Do not guess based on elapsed time.

Power down and restore

Disconnect LiPo first. Then power down USB and re-upload the normal Actual_Fly_Control.ino. The code cannot verify that the ESC stored calibration.

01 · setup()

Starts Serial at 115200 baud, attaches all four ESC outputs, then sets every attached ESC to the 1000 µs minimum. If any attachment fails, calibration remains blocked at minimum.

02 · setAllESCs()

Clamps the requested pulse width to 1000–2000 µs and sends the same value to all attached ESCs.

03 · PREPARE_MAX

Only an explicit serial command requests 2000 µs. It starts a 10-second confirmation window; maximum signal is never sent automatically at boot.

04 · loop() + serial command parser

The main loop reads one newline-terminated command. PREPARE_MAX enters the maximum-signal state; CONFIRM_MIN is accepted only in that state. The 10-second watchdog is checked again each loop.

05 · Failsafe + what the sketch cannot prove

Abort and timeout both request 1000 µs on all attached ESCs. The sketch cannot detect propellers, battery connection, motor RPM, the ESC tone sequence, or whether calibration was stored. Treat serial messages as requested output, not proof of calibration success.

const int escPins[] = {15, 6, 18, 9};
const int MIN_THROTTLE_US = 1000;
const int MAX_THROTTLE_US = 2000;
const int ESC_FREQUENCY_HZ = 50;
const unsigned long MAX_CONFIRM_WINDOW_MS = 10000;

void setAllESCs(int pulseWidthUs) {
  pulseWidthUs = constrain(pulseWidthUs, MIN_THROTTLE_US, MAX_THROTTLE_US);
  for (int i = 0; i < NUM_ESCS; i++) {
    if (escs[i].attached()) escs[i].writeMicroseconds(pulseWidthUs);
  }
}
